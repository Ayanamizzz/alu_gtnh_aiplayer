# 大脑端产线规划工具：设计与交付标准

## 已定目标

给小阿露一个真正可调用的产线计算工具：她选择配方、机型、配置、目标和约束，计算器负责机器负载、物料/流体流量、耗电、循环、副产物与瓶颈；她据结果修改方案。不是要求主人先画图，也不是驱动客户端GUI，更不依赖主人在线。

内部优先使用原版英文API、FactoryProject计划格式、机型/设置标识及原生计算结果，不另造中文规划语言，不为显示翻译改变计算身份。规划和给主人讲解是两层：对话线再用中文解释，中文名可作附注，不能取代内部标识。

用户已授权完成设计、自审、实现和整套验证；普通技术取舍自行决定，重大需求冲突/风险才请示。全部在独立功能分支，完成后请求合并，不提前合main、push或部署正式服。

## 选型

- 复用原作者维护的TypeScript计算实现 `jackwrichards/gtnh-factory-flow`，固定 `e493e36a64d5a226e6110fab8a765ae08c3bf7c5`。上游说明它的plan solver与Minecraft端是同一设计的逐行移植，提供共同数据集。
- `jackwrichards/gtnh-planner-mod` 固定beta.3 `69dd09fe21117d7b8558625dc9556723873942ca`，作机器目录/源语义及独立数值对照。已实测其Java引擎可脱离MC运行，但需JDK25；不把额外JDK版本要求引入Node24大脑的主运行路径。
- 不依赖汉化jar、客户端、Forge、网页账号、云服务、React/Next服务或浏览器。不要拷整个发布jar、图片、声音和游戏素材。
- 计算源码和HiGHS WASM的MIT许可允许复用。保留相应版权/许可和固定来源；README的产线工具段明确列所用/借鉴项目。无需重复造轮子或扩大许可调查。
- 开发时固定工具版本生成可审计的本地引擎bundle；运行时文件随大脑release打包，无联网下载、无新的常规npm安装步骤。保留源码来源、生成命令、hash与修改清单，不仅交一个来源不明的压缩文件。

## 能力边界

1. 规划图是带参数的配方节点和物料流，不是世界建筑图。此模块不自动放机器、改电路、接管道、写基地做法或开身体任务。
2. 配方搜索/路线取舍仍由模型。计算器只计算提供的图，不偷偷加入本地配方或把外部补料当成已经拥有。
3. 与total_materials互补：后者算有限批次材料树，这里算稳态每秒产出、机器容量与全线平衡。不能拿一次库存数量当无限持续供料。
4. 机器数学与图配平分开。复用上游已实现的机器规则；缺必要元数据、无法确认机型或特殊工艺不支持时明确列缺项，不套一个通用倍率伪装支持。
5. 所有结果是静态预测。机器成型、供电/供汽、真实库存、管线瓶颈、保护、实际产量仍须现有世界查询与后续执行验收。

## 用户/模型能完整走通的流程

1. 用find_recipes选择原料和工艺。
2. 调规划工具describe取得本地配方的稳定签名、端口、可用机型与参数说明；不按汉化显示名匹配。
3. 由模型构图、连物料、设目标速率、输入上限、机台上限/精确数量以及共享机组。
4. 求解。读负载、向上取整的建造数量（共享组不能逐节点独立取整）、输入/输出、耗电、短缺、强制补料/排料与假设。
5. 修改图或约束再算，可用run_program比较多个结果；旧方案与结果保留，不覆盖。
6. 在面板/结果中查看完整方案与报告，能导出结构化JSON。外部FactoryProject JSON可作为声明的静态输入，不是主流程前置条件；本批不解析gtnh1编码或网页分享链接。
7. 确定方案后，模型另查现场并调用既有材料/执行工具。导入、计算、查看都不触发施工。

## 接口与职责（供并行实现遵守）

### 引擎层（engine worker）

`brain/src/planner/engine.ts`，不依赖PackData或BridgeApi。
- 接受上游FactoryProject形状的纯JSON，调用上游calculateThroughput（完整机器数学+plan模式计算）。同时可导出原始SolveInput求解供对照测试。
- 公开 `PlannerEngine.calculate(project: unknown, options?: {timeoutMs?:number; signal?:AbortSignal}): Promise<unknown>`、`info()`、`close()`；结果保留完整原生报告，外围不能只靠一个solved布尔值判目标已满足。
- Node worker_threads隔离CPU计算；一次求解超时终止worker，后续调用能重新启动。有界队列、输入大小和输出大小限制，明确busy/timeout/invalid/error；不静默降级为主线程长时间求解。
- HiGHS加载/算法fallback状态必须可见，不能未知时仍声称使用了固定引擎。路径基于import.meta.url，发布目录/工作目录变化不影响WASM定位。
- 初始默认30秒求解上限，可通过配置在合理范围调；单次超时不破坏脑端其他工作。应用退出关闭worker。
- 引擎接口声明与使用示例先提交，供适配和工具层衔接。vendored代码不纳入本项目strict/noUnused审查，但我们自己的包裹层必须符合。

### 本地数据适配与规划模型（adapter worker）

`brain/src/planner/model.ts`、`catalog.ts`、`adapter.ts`、`report.ts`，不操作世界，不直接管理面板。
- 主输入沿用上游 `FactoryProject` 原生JSON（schemaVersion/recipes/nodes/storages/edges等），不要重造第二套ProductionPlan语言。describe把本地所选recipe ref转换为可直接放入原生project.recipes的记录，并给相应FactoryNode模板、机型/控制选项；本地来源签名放在独立metadata内。模型直接使用原版英文设置、port handles和约束语义。边、共享机组、targets、supply等依原版格式；额外检查不改写原始计划。
- describe(refs)给本地端口（输入/输出、物品id/meta或流体注册名、数量、概率、矿辞/候选）、机型选项、必需设置和支持范围；同资源多端口必须能明确指定，不能按名字任选。
- 创建本地配方快照。ref只是当前文件行号，持久方案保留完整签名（handler/输入输出及候选、流体、格位、EU/t、ticks、special/电路、概率、fake）。重新计算本地绑定方案校验数据版本/签名，不静默换配方。原版/外部或模型自写的原生配方也可作为声明的计算输入，明确标为declared/unverified，不伪称已和本服匹配；这是静态计算，不因未绑定就阉割原版图表达力。过期的本地绑定默认要求刷新或显式按旧假设计算。
- count0模具/催化剂/电路不能当持续消耗流；单独列一次性准备条件。矿辞需要具体化或显式保留等价类，不能把一个可能选项当已选择。
- 显式绑定机器目录/规则。优先使用上游稳定profile/map id、方块物品id/meta；汉化名仅显示。保留原版参数与默认值，但在结果里说清是采用哪个默认模型，不把默认机型当世界里已有。普通机器/多方块可覆盖多少以有完整参数的真实模型为准，未知不能猜。
- 尽量原样传递FactoryProject与原生结果，仅做本地来源绑定、合法性和约束检查。计算基准item/s、mB/s（GT L=mB）；原版view的/tick、/min等仅按其原有语义处理，不翻译成另一套单位协议。概率产物明确是期望量，不保证短批次收齐。
- 保留完整英文原生报告，另附清晰的状态解释：有效且满足给定目标、尚需外部供料/未满足、不可行、缺信息/不支持、计算失败。机台负载、整数建造需求、流量、电力、短缺、外部补流/排流、假设与诊断不能删掉；中文是展示附注，不重写算法结论。
- 固定目标与机器上限不能被上游pin优先级悄悄覆盖；硬容量约束须映射到pool/正确的上游约束。未连接端口明确当外部需求/排出而非免费真实资源。

### 工具、记录和手册（tool worker）

`brain/src/tools/production.ts`、`brain/src/planner/store.ts`、`workspace.ts`、工具入口测试及manuals/production.md。
- 一个库函数 `production_plan`，进入现有工具库索引，供两条线和查想子思维调用，不添一排专用常驻工具。
- actions：`describe`（配方/机型/端口）、`reference`（分页查原版英文类型、字段与注释，不限于示例）、`solve`（所给计划）、`read`（保存的计划/结果，按section分页）、`list`、`export`（机器可读JSON）。默认describe需明确参数，solve不隐式施工。与adapter类型联调；不要自己再实现配平/机器数学。
- 求解产生不可变分析记录（plan、resolved recipe snapshots、engine/source versions、report、时间、父记录可选）。同计划可按内容签名缓存；修改产生新记录，不覆盖旧结果。它是分析产物，不是向服务器发操作，helper只产生分析记录不改既有方案。
- 原始JSON完整保存，给模型的文字按节点/流/诊断分页，明确total/more；不能用截断JSON丢掉最后的短缺/警告。最重要的未满足条件必须在摘要里。
- 输入ID/文件名严格校验，不读调用方任意本地路径，不执行计划注释里的指令。外部共享方案仅是数据。
- 手册教会自行构图→求解→调整→再算，以及库存和速率、实际机台与负载、输入假设与真实供料的区别；不要退化为“请主人先导入规划器文件”。

### 主控集成

- 组装PlannerWorkspace，注入ToolContext/两条线/helpers；运行停止时关闭引擎，部署包包含所需静态运行文件。
- 面板提供只读计划列表、完整报告/JSON下载和简洁节点/流量展示，可沿用现有样式；不引入整个Next/ReactFlow站点、不把它塞进体素Draft。无需复杂交互画布才能完成大脑工具交付。
- README与第三方声明、运行诊断/版本、工具索引预算、公开协议/文档同步。

## 自审结论

该设计直接满足“脑端工具、AI自主构图、可靠计算、离线于游戏客户端”。复用原版计算模块，不重写数学，不让大脑操纵UI。数据适配、外部供给/未满足解释与失败隔离是主要风险，必须在真实工具入口验证，而不是仅证明一条公式能算。

不做：自动搜索所有配方并替模型定路线、整条工厂一键施工、云同步/账号、依赖玩家客户端求解、修改GT游戏机制。以上是与当前工具定位不同的功能，不作为本批交付前置。

## 实现收束

- 保留原版 Build/Plan/Solve/Pool；原版总EU/t、实际平均功率、整数机台满速功率和蒸汽分别记录。机台容量用有效的原版pin/pool语义，拒绝原版会忽略的零pin及会产生零功率假象的planning零seed。
- 共享卡不仅机型相同，解析后的实际电压等级、线圈和机型配置也必须一致；默认值不同就让模型显式选择共同设置，不自动挑最高档。
- 一次输入默认8MiB，展开section/边/端口和实际LP规模分别有预算；主线程准备之前检查同一预算，准备时间计入总deadline。默认30秒、至多120秒，一项运行两项等待。超时、取消、缺WASM、busy明确返回。
- `reference`让模型能分页查完整英文FactoryProject/Recipe/FactoryNode及solver类型，不因示例简单就丢掉复杂原版参数。只读固定文档，不接受文件路径，也不执行其中的代码。
- 配方库热替换需重启脑：检测加载源与当前路径身份不一致，不把旧fd内容签成新资料。NBT/培养物/聚变startup等必要数据缺失时明确阻止本地已验证绑定，外部声明仍可按假设计算。
- 面板只提供查看、分页和下载；记录不可变。静态循环不证明已有启动料，材料准备、物流、施工及实际运行仍由既有工具另外验收。

## 验收（整套，不以小探针代替）

- 真正的上游计算引擎，不mock掉数学：普通链、联产副产物、循环/返回料、共享机器、机器上限与目标冲突、源供给上限、孤岛/未锚定、概率输出与整数台数解释。
- 机器计算：普通/完美超频、并行/线圈等代表配置与上游golden或Java原生入口对照；缺设置/版本冲突明确拒绝，不填默认假数。
- 本地真实packdata选多条有意义的配方，完整describe→构图→solve→读报告→修改约束重算；不用真实模型key。脚本模型经真正脑工具入口走同样流程，验证它获得的信息足够进行下一步。
- 数据版本变更、错误资源连线、非有限数值、超时、并发/取消、重启后读方案、发布目录下WASM/引擎可用、无客户端/桥接离线仍可算。
- 面板实际看报告和下载；明确区分静态计算与现场事实。工具本身不能触发task.start。
- 全套测试/typecheck/打包检查和独立只读审查后交付；只修真实失败，不锁定错误旧行为。最后请求合并，不自动合main。
